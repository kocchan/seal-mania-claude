# 記事ブラッシュアップスキル

Slack for Claudeで人間と会話しながら、下書き記事をブラッシュアップする。

## タスク

### 1. 下書き確認

`output/new-releases/drafts/` から `approved: false` の下書きを取得して表示する。

表示形式:

```
新しい下書きが1件あります。

---

**【速報】ボンボンドロップシール「サンリオキャラクターズ moji」が5月15日発売！**

## ボンボンドロップシールに待望の新作登場！

（本文）

---

この内容でよろしいですか？修正したい箇所があればお知らせください。
```

### 2. 会話でブラッシュアップ

人間からの修正指示に応じて記事を改善する。

**よく使う修正指示:**

| 指示 | 対応 |
|------|------|
| 「もっとキャッチーに」 | 導入文やタイトルをより魅力的に |
| 「詳しく書いて」 | 情報を充実させる |
| 「短くして」 | 冗長な部分を削る |
| 「〇〇を追加して」 | 特定の情報を追記 |
| 「比較表を入れて」 | 前作との違いなどを表形式で |
| 「SNSの声を入れて」 | X/Threadsの反応を引用 |

修正案を提示する形式:

```
導入文を修正しました：

---

## ついに来た！サンリオ×ボンドロの最強コラボ第2弾！

「待ってました！」「可愛すぎて全種類集めたい！」

SNSで早くも話題沸騰中の新作が発表されました。

---

いかがでしょうか？
```

### 3. 承認

人間が「これでOK」「完璧」などと言ったら:

1. 下書きファイルを更新（ブラッシュアップ内容を反映）
2. `approved: true` に変更
3. git commit & push

応答形式:

```
下書きを更新しました。

📝 ファイル: output/new-releases/drafts/2026-05-01-sanrio-moji.md
✅ ステータス: approved: true
🔄 git push: 完了

この記事は次回のpost-flow（毎日17:00）でWordPressに投稿されます。
```

## フラグ更新

| 操作 | フラグ変更 |
|------|-----------|
| 「これでOK」 | `approved: false` → `true` |

## 入出力

| 種類 | パス |
|------|------|
| 入力 | `output/new-releases/drafts/*.md` (approved: false) |
| 出力 | `output/new-releases/drafts/*.md` (approved: true) |

## 実行環境

Slack for Claude（GitHub連携が必要）
