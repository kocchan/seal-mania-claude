# 全体アーキテクチャ

## 概要

人間のレビューが必要な作業はスマホやPCのClaude Codeで行い、人間が不要な部分はGitHub Actionsで自動化する。

この構成にした理由はコストを抑えるためである。Claude Maxプランの定額料金内でなるべく作業を完結させ、完全自動化が必要な部分のみGitHub ActionsとClaude APIで対応する（追加のAPI費用は発生するが許容する）。また出先でもSlack経由でコンテンツ制作ができるようにした。

## コンポーネント詳細

### 1. ローカル（Mac） - Claude Code CLI

**用途**: メインの作業環境

| 機能 | 説明 |
|------|------|
| 壁打ち・分析 | コンテンツのアイデア出し、データ分析 |
| レビュー | 下書きの品質チェック、改善提案 |
| cronで定期実行 | ローカルでのスケジュールタスク |
| ファイル作成・編集 | 記事・投稿の作成と編集 |

### 2. GitHub Repository

**用途**: 中央データストア & トリガーポイント

- すべてのコンテンツをバージョン管理
- GitHub Actionsのトリガー
- Slack for Claudeからの参照元

### 3. スマホ - Slack for Claude

**用途**: モバイルでのアイデア出し

| 機能 | 説明 |
|------|------|
| コンテンツ考案 | 移動中のアイデアメモ |
| 戦略壁打ち | 戦略の相談・検討 |

### 4. サーバー - GitHub Actions

**用途**: 自動化実行環境

| 機能 | 説明 |
|------|------|
| 定期自動投稿 | スケジュールに基づく自動投稿 |
| スケジュール実行 | cron式での定期タスク |

## フォルダ構成

```
seal-mania-claude/
├── .claude/
│   ├── skills/            # Skills（Claude Code用スキル定義）
│   └── agent/             # Agent（エージェント設定）
├── .github/workflows/     # GitHub Actions定義
├── scripts/               # 自動化スクリプト
├── docs/                  # 設計ドキュメント
├── knowledge/             # ナレッジ蓄積
└── output/
    ├── blog/
    │   ├── drafts/        # ブログ下書き
    │   ├── raw/           # 収集データ（JSON）
    │   └── published/     # ブログ投稿済み
    ├── x/
    │   ├── drafts/        # X下書き
    │   └── published/     # X投稿済み
    └── strategy/          # 戦略アイデア
```

## データ保存方針

| データ | 保存先 | 理由 |
|--------|--------|------|
| 投稿済みツイート | フォルダ内（Markdown） | Git履歴で管理、検索しやすい |
| 分析用記事 | Google Sheets | 一覧で見やすい、フィルタ・ソート可能 |
| 下書き・アイデア | フォルダ内（Markdown） | Claude Codeで直接編集 |
